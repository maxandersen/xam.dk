= xam.dk is now powered by Quarkus Roq
:page-layout: post
:page-author: Max Rydahl Andersen
:page-tags: Java, Quarkus, Roq, meta

This blog has quietly moved from Jekyll to https://iamroq.dev[Quarkus Roq], a static site generator built on Java and Quarkus.

== Why it took a while

I had wanted to get off Jekyll for ages. The last straw was when `jbang.dev` moved and I tried to migrate that site to Roq — and gave up. Qute instead of Liquid, a different content model, my pile of custom includes... it felt like more yak-shaving than I had patience for.

What changed my mind was watching a https://foojay.io[Foojay] video about Roq and then seeing that even https://quarkus.io[quarkus.io] itself — thousands of pages, versioned docs and all — had been migrated to Roq. If it could carry quarkus.io, it could certainly carry my little blog.

So I gave xam.dk another go. This time I leaned on an LLM, feeding it the https://iamroq.dev/docs/migrating/[Roq migration guide] and the ready-made prompts on that page. Honestly? It more or less did it. Templates converted, content moved, configuration mapped — I mostly reviewed, nudged, and fixed edge cases.

== Cool things I learned along the way

=== No frontmatter required
You don't even need YAML frontmatter anymore. This very post is *pure AsciiDoc* — the document title and `:page-*:` attributes in the header are picked up as page metadata directly. No `---` fences in sight.

=== Relativize is back — via a template method
My old Jekyll templates used `relativize_url` almost everywhere so links worked no matter where the site was served. Roq has no direct equivalent, but because it is Qute + Java, I added a tiny template extension:

[source,java]
----
@TemplateExtension
public class UrlExtensions {
    public static String rel(Page page, String target) { ... } // Path.relativize under the hood
}
----

So templates can now write `+{=page.rel('/assets/main.css')}+` and get a proper `../../assets/main.css` relative to the current page. That is the kind of thing that would have meant a plugin in Jekyll; here it is a few lines of Java.

NOTE: One gap: this only covers links I control in templates. Relative links *inside* rendered AsciiDoc/Markdown content aren't rewritten yet — so in-content image and page references still use absolute paths for now.

=== Old comments and webmentions, preserved
New comments are no longer possible (the old staticman/webmention services are gone), but every historical comment and webmention is kept and shown read-only. Likes, reposts and mentions render as a compact avatar facepile with counts; replies and comments show in full. The avatars are cached locally so there is no runtime dependency on a third-party service.

=== A good spring cleaning
Migrating was also a chance to delete a lot: dead staticman/recaptcha config, an unused contact form, and piles of theme vendor source files that were never served.

== Thanks

Thanks to the Roq team — this was genuinely fun once I stopped fighting it. If you have a Jekyll site gathering dust, the migration guide plus an LLM is a surprisingly good afternoon.
